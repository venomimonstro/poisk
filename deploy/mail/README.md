# Internet Mail deployment boundary

Sprint 26 keeps the Go application behind an authenticated HTTP gateway and delegates public SMTP to a separate Postfix-compatible MTA. The application must never listen on public SMTP ports and the browser must never receive relay credentials, DKIM private keys or the gateway shared secret.

## Components

1. **Poisk backend** — canonical mailbox/message state, inbound MIME validation, attachment quota/storage, delivery status and audit events.
2. **mail-gateway-worker** — leases durable outbound deliveries from PostgreSQL and submits signed envelopes to the private MTA bridge at `MAIL_MTA_BASE_URL/v1/outbound`.
3. **MTA bridge** — private HTTP service colocated with the MTA. It verifies the same HMAC contract as the application, enforces replay protection and injects accepted mail into local Postfix. It also calls the application internal gateway for recipient validation, inbound messages and delivery/bounce callbacks.
4. **Postfix-compatible MTA** — the only component listening on public SMTP. It is default-deny for relay and accepts local-domain recipients only when the recipient map confirms an ACTIVE Poisk mailbox/alias.
5. **DKIM signer** — runs at the MTA boundary. The private key is mounted from a secret/file and is never stored in PostgreSQL, repository files, environment examples or browser-visible configuration.

## Required private contracts

Outbound application -> MTA bridge:

- `POST /v1/outbound`
- request body is the bounded `MTAEnvelope` generated by `internal/mail/gateway_mta.go`
- headers: `X-Poisk-Gateway-Event`, `X-Poisk-Gateway-Timestamp`, `X-Poisk-Gateway-Signature`
- successful response: `{"remote_queue_id":"..."}`
- retries must be idempotent by the envelope `idempotency_key`

MTA bridge -> application:

- `POST /internal/mail-gateway/recipient` before accepting a local recipient
- `POST /internal/mail-gateway/inbound` after SMTP acceptance; raw RFC 5322 message is base64 encoded and remains bounded by the application MIME limits
- `POST /internal/mail-gateway/delivery-event` for final DELIVER or BOUNCE callbacks
- every request uses the same signed/replay-protected gateway headers

The gateway endpoint should be reachable only on the private service network. HMAC remains mandatory even on that network.

## Postfix relay policy

Use `postfix-main.cf.example` as the minimum boundary. Important properties:

- `mynetworks` contains loopback/private bridge injection only, never broad public CIDRs
- `smtpd_relay_restrictions = permit_mynetworks, reject_unauth_destination`
- the public mail domain is a virtual mailbox domain, not a catch-all relay domain
- `virtual_mailbox_maps` must be backed by the MTA bridge recipient adapter; unknown or inactive local recipients must return not-found before DATA acceptance
- message and recipient counts are bounded
- SMTP TLS is enabled at the MTA boundary

Do not replace the recipient map with a wildcard entry. A wildcard turns the service into a catch-all and violates Sprint 26 isolation requirements.

## DKIM / SPF / DMARC

1. Generate the DKIM key pair on the MTA host.
2. Mount the private key read-only, e.g. `/run/secrets/mail_dkim_private_key`; permissions should allow only the signer process.
3. Publish `<selector>._domainkey.<MAIL_DOMAIN>` TXT and place the expected public TXT value in `MAIL_DKIM_PUBLIC_TXT` so the worker readiness check can detect DNS drift.
4. Publish SPF for the actual outbound MTA addresses.
5. Publish DMARC for `_dmarc.<MAIL_DOMAIN>` with an explicit policy appropriate for rollout.
6. Start `mail-gateway-worker` only after `CheckInternetMailDNS` reports ready.

## Production enablement order

1. Keep `MAIL_INTERNET_ENABLED=false` while deploying schema/application changes.
2. Configure the private MTA bridge and Postfix boundary.
3. Configure recipient adapter, TLS, DKIM secret mount, SPF and DMARC.
4. Set a random `MAIL_GATEWAY_SHARED_SECRET` of at least 32 bytes on both application and MTA bridge.
5. Set `MAIL_DOMAIN`, `MAIL_DKIM_SELECTOR`, `MAIL_DKIM_PUBLIC_TXT` and `MAIL_MTA_BASE_URL`.
6. Validate that an unknown local recipient is rejected and that an arbitrary external-to-external SMTP relay attempt is rejected.
7. Set `MAIL_INTERNET_ENABLED=true` and start the Compose `internet-mail` profile for `mail-gateway-worker`.
8. Verify Admin aggregate gateway health; do not inspect bodies/recipient lists as a routine health signal.

Rollback is immediate: set `MAIL_INTERNET_ENABLED=false` and stop `mail-gateway-worker`. Canonical Mail Core data remains intact and internal Sprint 25 delivery continues to operate.
